# Support Routes

The support route is intentionally release-route dependent.

## Open Source On GitHub

Use GitHub Issues for bugs, enhancement requests, and public discussion. Add issue templates before release so users provide macOS version, Scéal version, reproduction steps, expected behavior, actual behavior, and whether the issue affects import/export/restore.

## Website Or Direct Download

Use a support email address or support form. The website should also link to:

- Privacy policy
- Data storage docs
- Backup and restore docs
- Known limitations
- Download integrity notes once signing/notarization is implemented

## Mac App Store

The App Store is not a full public issue tracker.

Apple provides App Store ratings/reviews and lets developers respond to reviews for macOS apps. Apple also provides TestFlight feedback with screenshots, crash comments, and general comments during beta testing.

For App Store submission, Apple still requires a Support URL. Apple's App Store Connect reference says the Support URL must lead to actual contact information so users can reach the developer about app issues, feedback, and feature requests.

Apple also requires a Privacy Policy URL for all apps.

Sources:

- [Support URL reference](https://developer.apple.com/help/app-store-connect/reference/app-information/platform-version-information)
- [Ratings and reviews](https://developer.apple.com/help/app-store-connect/monitor-ratings-and-reviews/ratings-and-reviews-overview/)
- [TestFlight feedback](https://developer.apple.com/help/app-store-connect/test-a-beta-version/view-tester-feedback/)
- [App privacy](https://developer.apple.com/help/app-store-connect/reference/app-information/app-privacy/)
